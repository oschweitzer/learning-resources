# Amazon S3

## À quoi ça sert

Stockage d'objets durable pour sauvegarde, DR, archive, data lakes, sites statiques, hébergement d'applis et de médias.

## Concepts clés

- Les objets vivent dans des **buckets**, créés dans **une région**. Noms dans un namespace global partagé (option *account regional namespace* pour réutiliser un nom entre régions). Minuscules, pas d'underscore, pas une IP, commence par lettre ou chiffre.
- La **key** est le chemin complet (prefix + nom) ; pas de vrais répertoires. Objet : métadonnées, jusqu'à 10 tags, version ID si versioning.
- **Durabilité 99,999999999 %** (11 neuf) pour toutes les classes ; disponibilité selon la classe (99,99 % Standard).
- **Classes** : Standard ; Intelligent-Tiering (accès inconnu, petit coût de monitoring par objet, pas de frais de retrieval) ; Standard-IA ; One Zone-IA (1 AZ) ; Glacier Instant Retrieval ; Glacier Flexible Retrieval (Expedited 1 à 5 min, Standard 3 à 5 h, Bulk 5 à 12 h gratuit) ; Glacier Deep Archive (Standard 12 h, Bulk 48 h) ; Express One Zone (directory bucket, 1 AZ, ms à un chiffre, jusqu'à 10x plus rapide).
- IA et Glacier : durée minimale facturée (30 / 90 / 180 jours) et taille minimale facturée de 128 KB (40 KB pour Flexible et Deep Archive).
- **Intelligent-Tiering** : Frequent par défaut, Infrequent après 30 jours, Archive Instant après 90 jours, Archive Access (dès 90 j) et Deep Archive Access (dès 180 j) optionnels.
- **Lifecycle** : transitions (ex. Standard-IA après 30 j, Glacier après 180 j) et expirations (logs, anciennes versions, multipart incomplets), par prefix ou tags. **Storage Class Analysis** : recommande Standard → Standard-IA uniquement (24 à 48 h pour démarrer).
- **Versioning** : au niveau bucket ; écraser crée une version, supprimer ajoute un *delete marker* ; objets antérieurs = version null ; suspendre garde les anciennes versions.
- **Réplication** : versioning requis sur les 2 buckets + IAM role ; asynchrone ; cross-account possible. CRR (compliance, latence, cross-account), SRR (agrégation de logs, prod↔test). Seuls les **nouveaux** objets sont répliqués (Batch Replication pour l'existant et les échecs). Delete markers réplicables en option ; suppressions d'une version précise **jamais** répliquées ; pas de chaînage A→B→C. **RTC** : 99,99 % des objets en 15 min.
- **Performance** : ≥ 3 500 PUT/COPY/POST/DELETE et 5 500 GET/HEAD par seconde **par prefix**, pas de limite de prefixes. Multipart recommandé > 100 MB, obligatoire > 5 GB (jusqu'à 10 000 parts). **Transfer Acceleration** (edge le plus proche puis réseau AWS). **Byte-range fetches**.
- SSE-KMS ajoute des appels KMS (GenerateDataKey/Decrypt) comptés dans les quotas KMS (5 500 à 30 000 req/s selon région) → **S3 Bucket Keys**.
- **Batch Operations** (liste depuis S3 Inventory, filtrée avec Athena) : métadonnées, copie, chiffrement, ACL/tags, restore Glacier, Lambda. **Event notifications** → SNS, SQS, Lambda (resource policies sur la destination) ; vers **EventBridge** pour filtrage JSON avancé, plus de cibles, archive/replay. **Storage Lens** (métriques gratuites ~28/14 jours ; avancées 15 mois). **Requester Pays**.
- **Sécurité** : IAM + bucket policies ; ACL désactivées par défaut (bucket owner enforced) ; **Block Public Access** activé par défaut, remplace toute policy qui rendrait public. **Access points** (DNS + policy par appli ; VPC origin access point via VPC endpoint).
- **Chiffrement** : SSE-S3 (AES-256, défaut sur tous les nouveaux buckets/objets), SSE-KMS (audit CloudTrail, quotas KMS), DSSE-KMS (double couche), SSE-C (clé fournie à chaque requête, HTTPS obligatoire), client-side. Forcer HTTPS : deny si `aws:SecureTransport` est false. Les bucket policies sont évaluées avant le chiffrement par défaut.
- **CORS** : un site du bucket A qui charge des assets du bucket B → configurer CORS sur B avec l'origin de A. **MFA Delete** : versioning requis, seul root peut l'activer, via CLI. **Server access logs** : bucket cible dans la même région et jamais le bucket surveillé (boucle).
- **Pre-signed URLs** : accès temporaire avec les permissions de l'émetteur ; jusqu'à 12 h depuis la console et 7 jours (604 800 s) depuis CLI/SDK.
- **Object Lock** (versioning requis) : WORM par version. *Compliance* : personne, pas même root, ne peut supprimer ni raccourcir la rétention. *Governance* : override possible avec permissions spéciales. *Legal hold* : indéfini (`s3:PutObjectLegalHold`). Glacier Vault Lock = mécanisme WORM des vaults ; pour du neuf, Object Lock.
- **Site statique** : URL type bucket-name.s3-website-region.amazonaws.com ; 403 = bucket policy sans lecture publique ; en pratique CloudFront + OAC.
- S3 Object Lambda : fermé aux nouveaux clients depuis le 7 novembre 2025. Le Glacier autonome (vaults) a fermé aux nouveaux clients le 15 décembre 2025 ; les classes S3 Glacier restent valables.

## Limites et quotas

- Objet jusqu'à **50 TB** (décembre 2025 ; avant 5 TB) ; PUT simple jusqu'à 5 GB.
- Multipart : jusqu'à 10 000 parts.
- 10 tags par objet.
- 3 500 écritures / 5 500 lectures par seconde par prefix.
- Pre-signed : 12 h (console), 7 jours (CLI/SDK).
- Durées minimales : 30 (IA), 90 (Glacier IR/Flexible), 180 jours (Deep Archive).
- Taille minimale facturée : 128 KB (40 KB Flexible/Deep Archive).

## Tarification (logique)

- Les classes IA/Glacier ont des durées minimales de stockage : coûteux pour des données de courte vie.
- Intelligent-Tiering : petit frais de monitoring par objet, pas de retrieval fee.
- Requester Pays : le demandeur paie requêtes et sortie de données, le propriétaire paie le stockage.
- SSE-KMS : coût et quotas des appels KMS (atténué par Bucket Keys).

## Pièges d'examen

- Replication : versioning requis, nouveaux objets seulement, deletes de version jamais répliqués.
- SSE-C exige HTTPS.
- MFA Delete : root uniquement.
- Throttling avec SSE-KMS = quotas KMS.
- Snowball n'écrit pas directement dans Glacier : import S3 puis lifecycle.
- Durées minimales rendent IA/Glacier chers pour du court terme.
