# Amazon S3

## What it is for

Durable object storage for backup, DR, archive, data lakes, static websites, application and media hosting.

## Key concepts

- Objects live in **buckets**, created in **one region**. Names live in a shared global namespace (an *account regional namespace* option lets you reuse a name across regions). Lowercase, no underscores, not an IP, start with a letter or number.
- The **key** is the full path (prefix + name); there are no real directories. Objects carry metadata, up to 10 tags, and a version ID when versioning is on.
- **Durability 99.999999999%** (eleven nines) for every class; availability depends on the class (99.99% for Standard).
- **Classes**: Standard; Intelligent-Tiering (unknown access, small monitoring fee per object, no retrieval fee); Standard-IA; One Zone-IA (1 AZ); Glacier Instant Retrieval; Glacier Flexible Retrieval (Expedited 1-5 min, Standard 3-5 h, Bulk 5-12 h free); Glacier Deep Archive (Standard 12 h, Bulk 48 h); Express One Zone (directory bucket, 1 AZ, single-digit ms, up to 10x faster).
- IA and Glacier: minimum billable duration (30 / 90 / 180 days) and minimum billable object size of 128 KB (40 KB for Flexible and Deep Archive).
- **Intelligent-Tiering**: Frequent by default, Infrequent after 30 days, Archive Instant after 90 days, optional Archive Access (from 90 d) and Deep Archive Access (from 180 d).
- **Lifecycle**: transitions (e.g. Standard-IA after 30 d, Glacier after 180 d) and expirations (logs, old versions, incomplete multipart uploads), by prefix or tags. **Storage Class Analysis**: recommends Standard -> Standard-IA only (24 to 48 h to start).
- **Versioning**: bucket level; overwriting creates a version, deleting adds a *delete marker*; objects uploaded earlier have version null; suspending keeps old versions.
- **Replication**: versioning required on both buckets + IAM role; asynchronous; cross-account possible. CRR (compliance, latency, cross-account), SRR (log aggregation, prod<->test). Only **new** objects replicate (Batch Replication for existing objects and failures). Delete markers can optionally replicate; deletions of a specific version are **never** replicated; no chaining A->B->C. **RTC**: 99.99% of objects within 15 min.
- **Performance**: >= 3,500 PUT/COPY/POST/DELETE and 5,500 GET/HEAD per second **per prefix**, no limit on prefixes. Multipart recommended > 100 MB, mandatory > 5 GB (up to 10,000 parts). **Transfer Acceleration** (nearest edge then AWS network). **Byte-range fetches**.
- SSE-KMS adds KMS calls (GenerateDataKey/Decrypt) that count against KMS request quotas (5,500 to 30,000 per second depending on region) -> **S3 Bucket Keys**.
- **Batch Operations** (list from S3 Inventory, filtered with Athena): metadata, copy, encrypt, ACLs/tags, Glacier restore, Lambda. **Event notifications** -> SNS, SQS, Lambda (resource policies on the destination); to **EventBridge** for advanced JSON filtering, more targets, archive/replay. **Storage Lens** (free metrics ~28 / 14 days; advanced 15 months). **Requester Pays**.
- **Security**: IAM + bucket policies; ACLs disabled by default (bucket owner enforced); **Block Public Access** on by default, overrides any policy that would make data public. **Access points** (DNS + policy per application; VPC origin access point through a VPC endpoint).
- **Encryption**: SSE-S3 (AES-256, default on all new buckets/objects), SSE-KMS (CloudTrail audit, KMS quotas), DSSE-KMS (dual layer), SSE-C (key sent on every request, HTTPS mandatory), client-side. Force HTTPS: deny when `aws:SecureTransport` is false. Bucket policies are evaluated before default encryption.
- **CORS**: a site on bucket A loading assets from bucket B -> configure CORS on B with A's origin. **MFA Delete**: versioning required, only root can enable it, via CLI. **Server access logs**: target bucket in the same region and never the monitored bucket (loop).
- **Pre-signed URLs**: temporary access with the permissions of the issuer; up to 12 h from the console and up to 7 days (604,800 s) from the CLI/SDK.
- **Object Lock** (versioning required): WORM per object version. *Compliance*: nobody, not even root, can delete or shorten retention. *Governance*: override with special permissions. *Legal hold*: indefinite (`s3:PutObjectLegalHold`). Glacier Vault Lock was the WORM mechanism of vaults; for new designs use Object Lock.
- **Static website**: URL like bucket-name.s3-website-region.amazonaws.com; 403 = bucket policy without public read; in practice CloudFront + OAC.
- S3 Object Lambda: closed to new customers since 7 November 2025. Standalone Glacier (vaults) closed to new customers on 15 December 2025; the S3 Glacier classes are unaffected.

## Limits and quotas

- Object up to **50 TB** (December 2025; previously 5 TB); single PUT up to 5 GB.
- Multipart: up to 10,000 parts.
- 10 tags per object.
- 3,500 writes / 5,500 reads per second per prefix.
- Pre-signed: 12 h (console), 7 days (CLI/SDK).
- Minimum durations: 30 (IA), 90 (Glacier IR/Flexible), 180 days (Deep Archive).
- Minimum billable size: 128 KB (40 KB Flexible/Deep Archive).

## Pricing (logic)

- IA/Glacier classes have minimum storage durations: costly for short-lived data.
- Intelligent-Tiering: small monitoring fee per object, no retrieval fee.
- Requester Pays: the requester pays requests and data transfer out, the owner pays storage.
- SSE-KMS: cost and quotas of KMS calls (reduced by Bucket Keys).

## When to use it vs alternatives

- Classes -> [[s3-storage-classes]]. Disk / file -> [[ebs-vs-efs-vs-s3]]. Worldwide distribution -> [[cloudfront]]. SQL on S3 -> [[athena]].

## Exam traps

- Replication: versioning required, new objects only, version deletes never replicated.
- SSE-C requires HTTPS.
- MFA Delete: root only.
- Throttling with SSE-KMS = KMS quotas.
- Snowball cannot write directly to Glacier: import to S3 then a lifecycle rule.
- Minimum durations make IA/Glacier expensive for short-term data.
